직접·전이·테스트 의존성 버전은 `requirements-lock.txt`에 고정했다. OS와 Python 버전에 맞는
바이너리 wheel은 다를 수 있다. Python 내장 SQLite는 pip 패키지로 고정하지 않는다.
Linux·Render 환경은 별도 검증 대상이며 이 파일은 해시 기반 공급망 잠금 파일이 아니다.

기존 `.venv`·`.env`·DB는 유지했다. 실행 중인 로컬 서버는 Python 3.13 환경으로 재시작했다.
프로젝트 지원 범위는 Python 3.12 이상 3.14 미만이다. 새 설치는 README의 3.13 설치 순서를 따른다.

```powershell
py -3.13 -m venv .venv313
.\.venv313\Scripts\python.exe -m pip install -r requirements-lock.txt -e ".[dev]"
.\.venv313\Scripts\python.exe -m culturebridge.check_environment
.\.venv313\Scripts\python.exe -m pip check
.\scripts\check.ps1 -Environment .venv313
.\scripts\run.ps1 -Environment .venv313
```

기존 환경이 있는 경우 `venv` 생성은 생략한다. 버전 검사에는 키 값을 출력하지 않는다.
팀원들이 통상 `.venv`를 쓰는 경우 이름만 `.venv`로 바꾸고 스크립트의 Environment 인자를 생략한다.

## 세 연결의 적용 범위

① 주장 검증 → 추가 공식 자료 → 재검증

- 저장 원문으로 개별 주장·인용을 먼저 점검한다.
- 부족한 주장에 등장하는 선택 유산을 대상으로 공식 자료를 한 번 추가 조회한다.
- 새 자료로 재검토하며, 미해결 부분은 판단 보류한다. 원문 그대로인 문장은 불필요하게 재검색하지 않는다.
- 조회 실패 시 기존 근거를 유지한다. 사용자 주장·답변과 기존 비교 저장본은 덮어쓰거나 저장하지 않는다.
- 응답·화면에 재검색 횟수·실행 기록·추가 자료 상태·출처를 표시한다.

② Gemini 퀴즈 초안 → 로컬 검사 → 저장·채점

- 수준·목표·분량·유효한 추출 근거를 전달해 4지선다 5문항 초안을 요청한다.
- 문항 수·선택지 수/중복·근거 인덱스·질문 대상·정답의 후보/인용 일치·목표 반영·초급 길이를 검사한다.
- 생성된 해설은 사실로 공개하지 않는다. 코드를 통해 검사된 후보와 실제 인용을 해설로 연결한다.
- 실패·시간 초과·사용량 제한 시 규칙 기반 문항을 제공한다. 채점은 Python, 정답은 제출 전 비공개다.
- 의미·난도·오답의 교육적 타당성은 자동 검사만으로 확정할 수 없으므로 사람의 검토가 필요하다.
- 긴 새 문항 생성은 브라우저 연결 후 별도 작업으로 실행하며 저장된 퀴즈 재조회는 재호출하지 않는다.

③ 커리큘럼 → 비교·퀴즈의 목표 일관성

- 웹과 키오스크에서 짧게·기본·깊게 분량을 선택한다.
- 짧게는 우선 2항목, 기본은 목표 항목, 깊게는 양쪽 원문·대상 범위·대체 해석 확인 단계를 제공한다.
- 비교는 같은 초점 순서로 정렬하며 보조 항목을 구분한다. 공식 근거가 부족하면 대체 출처 확인 활동을 안내한다.
- 퀴즈는 같은 목표를 우선하고 항상 5문항이다. Gemini 초안은 최소 3문항의 목표 항목 연결을 검사한다.
- 규칙 기반 대체 문항은 확보된 근거 읽기·출처·보류 원칙을 다룬다. 없는 목표 사실을 지어내지 않는다.
- 자유 목표는 지원 주제 키워드 기반이며, 임의 주제의 완전한 생성형 수업이나 학습 시간 측정은 아니다.

## 실제 연결과 남은 확인

- 3.13 서버에서 초급·종교·짧게 탐구를 실행했다. 학습 순서와 첫 비교 항목이 종교적 배경을 우선하고 5문항을 반환했다.
- 저장 비교: `caf7d166-2e04-4477-a79a-e01a8a42d8ba` (로컬 DB에만 존재).
- 대안탑→호류지 직접 영향 주장: 추가 조회 1회, 원문 재검토 후 `insufficient_evidence`로 보류했다.
- 실제 Gemini 퀴즈 호출은 서버 오류·형식 실패 이후 HTTP 429 사용량/요청 제한을 확인했다. 추가 호출은 멈췄다.
- 따라서 실제 Gemini 퀴즈 생성 성공은 확인하지 못했다. 유효 초안의 생성·저장·채점 연결과 잘못된 초안의 대체 경로는 모의 테스트로 검증했다.
- 실제 브라우저 클릭·모바일·키오스크 터치·화면 읽기 및 교육자 품질 검토는 별도로 남아 있다.

## API 변경

- `POST /api/explorations`: `amount=brief|standard|deep` 추가. 생략하면 standard로 기존 요청과 호환된다.
- 응답 및 비교 저장본에 amount와 목표별 근거 부족 안내 learning_notices를 포함한다.
- `POST /api/claims/verify`: retry_count, execution_trace, collected_sources를 추가 반환한다.
- 재검색의 추가 자료는 응답과 기관별 캐시에만 반영한다. 과거 비교·퀴즈 근거 저장본은 수정하지 않는다.
- 자유 목표는 최대 200자, 요청 목표·분량 enum은 FastAPI에서 검증한다.

- Python 3.13.15: 172개 테스트 통과(37.07초).
- 두 환경에서 Ruff 검사·62개 Python 파일 포맷 검사 통과, 잠금 파일의 87개 패키지 버전 일치.
- 두 환경의 pip 의존성 검사에서 충돌 없음.
- 유효 Gemini 초안·잘못된 정답·중복/복수 정답·잘못된 출처·잘못된 질문 대상·초급 길이·429 대체 경로를 검사했다.
- 주장 재검색 1회·재검토·미해결 보류·원문 일치 시 재검색 생략·기존 저장본 불변을 검사했다.
- 수준/분량별 학습 계획·목표별 비교 순서·근거 부족 안내·API 목표 유지·긴 퀴즈 로딩 응답을 검사했다.
- 최종 서버에서 상태·홈·키오스크·저장 퀴즈·저장 비교 HTTP 200, 잘못된 분량 요청 HTTP 422를 확인했다.
