# 대화에서 설명과 비교 학습 연결

2026년 11월 10일

경복궁에 대해 알고 싶다는 요청이 신편 한국사 검색 링크로 끝나는 문제를 수정했다. 문화유산 이름을 식별하면 국가유산청 검색과 상세 원문 읽기를 거쳐 대화 안에 설명하고, 내부 상세 페이지와 비교 학습으로 연결한다. 일반 소개는 네 가지 비교 항목뿐 아니라 원문의 개요도 설명 근거로 사용한다.

국가유산청 검색에서는 개별 전각이 먼저 정렬될 수 있다. 검색 상한을 50건으로 두고, 같은 이름의 유산을 찾아 앞에 배치한다. 전체 경복궁을 찾지 못했을 때 근정전이나 경회루를 경복궁 전체로 대신 설명하지 않는다. 모호한 결과는 사용자가 선택한다.

Gemini가 실패한 실행에서는 추가 모델 요청을 중단한다. 공식 원문을 읽을 수 있으면 기본 설명과 다음 학습 경로를 제공한다. 이해도를 자동 판단하거나 이를 Gemini가 생성한 설명으로 표시하지 않는다. 실패 종류와 상태 코드는 학습 실행 기록에 남기되 키나 SDK 예외의 원문은 저장하지 않는다.

실제 경복궁 조회에서 국가유산청 원문과 내부 비교 경로를 확인했다. Gemini의 실제 학습 요청 검사는 504 응답 시간 초과와 429 사용 한도 제한으로 정상 생성까지 확인하지 못했다. 마지막 429 이후에는 추가 Gemini 요청을 하지 않았다. 현재 모델이나 계정의 사용 한도 해소가 필요하며 성공 여부는 답변의 표시와 실행 기록에서 구분한다.

Gemini 3 계열의 대화용 계획과 설명 요청에는 LOW thinking 설정을 적용한다. 응답을 잘라내는 대신 추론 수준으로 지연을 줄이는 방향은 [Google 공식 안내](https://ai.google.dev/gemini-api/docs/thinking)를 따른다. 모델이나 계정의 요금제를 자동 변경하지 않는다.

신편 한국사의 제목·링크를 그 본문을 읽은 것처럼 설명하는 기능은 추가하지 않았다. 자료 이용 조건과 근거 검사를 유지한다.

전체 회귀 검사 846개 통과, 1개 건너뜀. 이후 기존 링크 전용 대화의 이어가기 복구까지 보완하고 관련 검사 25개를 통과했다. Ruff 검사와 전체 Python 형식 검사도 통과했다. 8081 확인용 서버는 수정본으로 재시작했으며 기존 대화 기록을 유지한다.

## 실제 사용 서버 확인

이후 사용자 화면은 8080과 `data/culturebridge.db`를 사용하고, 위 검증 서버는 8081과 별도 DB를 사용하고 있음을 확인했다. 8081의 성공을 실제 사용 서버의 성공으로 보고한 것은 잘못된 확인이었다.

실제 8080을 현재 `.env`의 `gemini-3.1-flash-lite`와 Gemini 사용 상태로 다시 시작했다. 동일한 8080 API에서 “경복궁에 대해 말해주세요”를 별도 테스트 세션으로 3회 검증해 모두 `gemini_grounded_rewrite`를 확인했다. 소요 시간은 8.24초, 9.36초, 7.48초였고 실패 안내는 없었다. 관련 검사 25개도 통과했다. 혼동을 막기 위해 별도 8081 검증 서버는 종료했다.

## 일반 실행의 AI 모드와 오류 구분

사용자가 서버를 다시 실행한 뒤 `planner_not_available`가 기록되는 사례를 확인했다. 프로젝트 `.env`는 AI 사용 상태였지만 서버에서 호출 전에 중단됐다. 실행 스크립트가 이전 터미널의 꺼짐 환경변수를 그대로 상속할 수 있어, 일반 실행은 AI를 켜고 명시적 `-Offline`만 끄도록 변경했다. 키가 없으면 시작 단계에서 실패하도록 했다. 설정 파일 경로도 프로젝트 루트로 고정했다.

`/api/ai-status`와 설정 화면에 서버가 읽은 사용 여부, 키 존재 여부, 모델을 표시한다. 키 값은 반환하지 않는다. 꺼짐과 키 누락을 실행 기록에서 구분하며, 이전 실패는 마지막 요청 결과로 표시한다. 설정이 복구된 이전 요청에는 다시 답변받기 버튼을 제공한다.

이후 Google 503 응답도 실제 관찰했다. 500·502·503만 최대 한 번 재시도하고, 429·403·504는 재시도하지 않는다. SDK의 HTTP 모의 응답으로 503만 재시도하는 것을 검증했다. 최종 8080 실제 생성 검사는 3회 모두 성공했으며 32.34초, 11.62초, 11.81초가 걸렸다. 첫 응답의 지연 때문에 모든 요청의 속도·안정성을 보장하는 결과로 해석하지 않는다.

전체 검사에서 858개 통과·1개 건너뜀을 확인했고, 꺼짐 안내 문구 변경에 따른 기존 기대값 1개를 수정한 뒤 관련 검사 25개와 해당 항목 재검사를 통과했다. 앞선 AI 상태·대화·API 관련 검사 75개도 통과했다. Ruff와 189개 Python 파일 형식 검사, PowerShell 구문 검사를 통과했다.

## 11월 11일: 자동 재시도와 대화 목록 정리

실제 8080 서버가 `.env`와 달리 `enabled:false`로 실행 중인 것을 `/api/ai-status`에서 확인했다. 해당 CultureBridge 프로세스를 Gemini 활성 모드로 다시 시작했고 같은 8080에서 새 익명 대화의 “경복궁에 대해 말해주세요” 요청이 약 9초 만에 `planner=ai`, `gemini_grounded_rewrite`, 오류 없음으로 끝났다. 기존 서버 프로세스는 코드 수정이나 `.env` 변경만으로 실행 모드가 바뀌지 않는다.

대화용 Gemini HTTP 요청은 최초 호출 후 429·500·502·503·504 및 연결 시간 초과에 최대 5회 재시도한다. 403 등 비재시도 오류와 설정 누락은 즉시 구분해 안내한다. 재시도 후에도 실패하면 Gemini가 생성한 설명인 것처럼 기본 안내를 표시하지 않고 실패를 명시한다. 명시적 오프라인 실행은 기존 공식 자료 탐색을 유지한다. 대화 전체 시간 예산은 기본 180초다.

첫 질문과 이어지는 질문 모두 기다리는 동안 ‘생각 중…’ 표시를 보여준다. 이전 실패의 수동 재시도 버튼은 없앴다. 왼쪽 대화 목록은 20개씩 더보기로 불러오고 내부에서 스크롤한다. 각 행의 점 세 개 메뉴에서 확인 후 해당 브라우저 소유 대화만 삭제한다.

## 다보탑 질문의 Gemini 설명 미사용 원인

11월 11일 실제 다보탑 대화 기록은 `planner=ai`였으나 설명 초안의 인용 검사가 `unsupported_span_or_number`로 끝나 `local_guide`가 표시됐다. 대상 “경주 불국사 다보탑”의 공식 상세 원문에 다보탑 문단이 있음에도, 개요 추출이 첫 문단인 불국사 일반 소개를 선택했다. Gemini 독립 검토는 이 문단이 다보탑 질문에 답하지 않는다고 정확히 거절했다. 원문 뒤쪽의 “전해진다”를 앞쪽의 다른 문장에도 요구한 검증 범위 오류도 있었다.

개요는 대상 이름이 실제로 나오는 공식 문단을 선택하고, 기존 대화에 저장된 잘못된 개요도 이어서 학습할 때 다시 읽어 교체한다. 불확실성은 각 설명 문장이 인용한 근거에만 적용한다. 초안 형식 검사 또는 독립 검토가 거절하면 원문 안전 검사를 유지하며 최대 5회 새 초안을 요청한다. 같은 다보탑 자료로 실제 Gemini 초안과 독립 검토가 모두 통과해 `gemini_grounded_rewrite`가 생성되는 것을 확인했다. 전체 검사에서는 869개 통과·3개 실패·1개 건너뜀이었고, 재시도 정책에 맞게 세 테스트를 수정한 뒤 관련 58개가 통과했다.
