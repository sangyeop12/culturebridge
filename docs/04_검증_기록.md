# 6. 수행 계획 및 검증 기록

□ 6.1 예외 처리

- 존재하지 않는 문화유산의 퀴즈: 오류 안내와 처음으로 버튼을 표시한다.
- 동일 문화유산 비교·퀴즈: 저장 및 생성 전에 서로 다른 대상 선택을 안내한다.
- 존재하지 않거나 대상이 다른 저장 ID: 복귀 화면을 표시한다.
- 잘못된 학습 수준: 초급으로 전환하고 전환 사실을 안내한다.
- DB 실패: 화면은 재시도·복귀를 안내하고 API는 상세 경로를 노출하지 않는 503을 반환한다.
- 질문 처리 실패: 알림을 표시하고 질문 버튼을 다시 활성화한다.
- 채점 실패: 결과 표시 및 완료 처리를 진행하지 않고 재시도를 안내한다.

□ 6.2 접근성 보완

- 키오스크 문화유산 선택을 기본 버튼으로 제공한다.
- 키보드 포커스 테두리, 질문·주장·검색 입력 이름, 퀴즈 문항별 라디오 그룹 이름을 제공한다.
- 질문·주장·채점 결과에 role=status 및 aria-live=polite를 적용한다.
- 문서 언어를 ko로 설정한다.
- 작은 화면에서 비교·문화유산 선택을 한 열로 배치한다.
- 키오스크 버튼과 라디오 선택 영역의 최소 높이를 72px로 설정한다.

□ 6.3 확인 결과

- 자동 테스트 58개 통과. 잘못된 UI 경로·저장 실패·API 503 응답을 포함한다.
- Ruff 검사 통과.
- 실제 브라우저에서 두 텍스트 입력의 접근 가능한 이름, 결과 알림 영역 2개,
  문서 언어 ko를 확인했다.
- 모바일 크기 변경 검사에서 브라우저 연결이 시간 초과되었다. 모바일 배치 실측,
  터치 높이 실측, 키보드 전체 이동 및 화면 읽기 프로그램 검증은 미완료다.
- 시간 초과 이후 뷰포트 복구도 응답을 확인하지 못했다. 해당 브라우저가 작은 크기로
  남아 있다면 사용자 화면에서 크기 설정을 확인해야 한다.
- 접근성 기준 전체 준수를 판정한 기록은 아니다.

□ 6.4 로컬 시연 준비 검증

- 실행 사전 점검: Python 3.12.14와 필수 패키지 import 정상.
- scripts/check.ps1: Ruff 검사·형식 검사 및 테스트 66개 통과.
- 검색 → 추천 → Agent 탐구 → 비교 저장/조회 → 자유 질문 → 주장 검증 →
  고급 퀴즈 채점 → 학습 기록 저장을 임시 DB에서 통합 검증했다.
- API 키가 설정된 상태를 모의해 오프라인 모드가 자동 호출을 막는지 확인했다.
- scripts/run.ps1 -Offline으로 실제 서버를 실행했다.
- /api/health·/·/kiosk·/comparisons·/docs 모두 HTTP 200을 확인했다.
- Gemini 실제 호출과 외부 배포는 이번 검증에 포함하지 않았다.

□ 6.5 국가유산청 API 및 Gemini 근거 연결 검증

- 외부 목록 API에서 석굴암 검색 5건, 상세 API에서 석굴암 본문 1,299자를 수집했다.
- 별도 API 키 없이 HTTPS 서버 요청으로 조회했다.
- 공식 원문 페이지 HTTP 200과 조회 캐시 재사용을 확인했다.
- 원문·URL·조회 시각 저장, 잘못된 XML·엔티티 확장 차단, 유산 코드 불일치,
  외부 장애·만료 캐시 표시를 모의 검증했다. 전체 테스트 75개 통과, Ruff 검사 통과.
- 실제 질문 API에서 used_ai=true와 국가유산청 API 출처 ID 반환을 확인했다.
- 기존 요약에 없는 건립 당시 이름 질문에 공식 본문의 석불사라는 이름이 응답에 포함됐다.
- 이는 한 가지 실제 호출 점검이며 답변 품질 전체를 보장하지 않는다.
- 현재 수집 원문을 Gemini 근거로 연결하는 자동 매핑은 석굴암에 적용된다.
  일반 검색 유산의 비교·퀴즈 데이터 변환과 UNESCO 직접 연동은 미구현이다.

□ 6.6 공식 위치정보 검증

- 국가유산공간정보 spca.do API를 키 없이 호출하고 석굴암 위치를 일치 확인했다.
- 응답의 UTM-K X·Y와 상세 API 위도·경도를 분리했다. 임의 좌표 변환은 하지 않았다.
- 실제 석굴암 상세 API 위도 35.794852, 경도 129.349242를 확인했다.
- 공식 상세 화면 HTTP 200과 위치 조회 버튼 포함 여부를 확인했다.
- 같은 이름의 중복 후보·다른 지역·없는 좌표·NaN·만료 캐시 장애 처리를 모의 검증했다.
- 전체 테스트 83개, Ruff 및 형식 검사 통과.
- 지도 링크를 제공하며 지정구역·보호구역 경계 시각화는 미구현이다.

□ 6.7 UNESCO 영문 XML 연결

- 자동 다운로드·검색 API·목록 UI·로컬 XML 가져오기 명령을 구현했다.
- 공식 XML 주소의 실제 서버 요청은 HTTP 403이며 성공 수집으로 기록하지 않는다.
- 예제 XML로 검색·페이지 조회·캐시·다운로드 실패·잘못된 XML 거부를 모의 검증했다.
- 초기 연결 테스트 92개 통과.
- 배포 이용 조건 링크, 저작권 및 공식 홈페이지·개별 유산 링크를 표시한다.
- 원문 번역·요약 및 Gemini 근거로의 전달은 이번 구현에 포함하지 않는다.

□ 6.8 UNESCO 실제 파일 가져오기

- 사용자가 다운로드한 unesco.xml (2,497,072바이트)을 가져와 세계유산 1,273건을 저장했다.
- API에서 ID 660·736·1442의 실제 항목과 정상 캐시 상태를 확인했다.
- 실제 브라우저에서 호류지 이름·국가·등재연도·공식 링크 표시를 확인했다.
- 숫자 ID 검색을 부분 일치에서 정확한 일치로 변경하고 회귀 테스트를 추가했다.
- 원본 파일은 다운로드 폴더에 유지하고 런타임 DB는 GitHub 업로드에서 제외했다.
- 직접 서버 다운로드의 403 제한은 여전히 남아 있으며 데이터는 파일 가져오기로 등록했다.

□ 6.9 UNESCO 자동 갱신 해결

- 기존 XML 주소의 응답에서 Cloudflare 확인 페이지와 HTTP 403을 확인했다.
- 공식 DataHub whc001의 메타데이터·레코드·JSON export API HTTP 200을 확인했다.
- 실서버에서 이름·국가·ID·등재연도 1,273건을 자동 수집하고 format=json으로 저장했다.
- 숫자 ID 660의 호류지 항목, 실제 수집 출처 URL 및 stale=false를 확인했다.
- XML 캐시를 JSON으로 전환하는 DB 마이그레이션과 실패 시 이전 자료 보존을 테스트했다.
- 자동 갱신 경로는 해결했으며 원래 XML 서버의 접근 제한 자체를 해제한 것은 아니다.

□ 6.10 한글 매칭 및 검색 자동완성

- 한글 별칭·공백·전각 숫자·정확한 국가 필터와 로컬 추천 결과를 테스트했다.
- 전체 테스트 104개 통과, Ruff 및 형식 검사 통과.
- 실제 API에서 호류지→660, 석굴암→736, 대안탑→1442 및 일본 27건을 확인했다.
- 실제 추천 API에서 '호' 입력에 호류지 별칭을 반환하는 것을 확인했다.
- 화면에 제안 버튼·Tab 완성·Enter 검색을 구현했다.
- 브라우저 연결 시간 초과로 이번 UI의 입력·제안 선택 직접 조작 검증은 미완료다.

□ 6.11 Agent 공식 자료 수집

- 전체 테스트 109개와 Ruff·형식 검사를 통과했다.
- 선택한 두 유산의 수집 호출, 장애·만료 자료 상태, 유산군 범위, 잘못된 ID 사전 차단,
  저장된 수집 본문 보존을 모의 검증했다.
- 실제 /api/explorations에서 석굴암 국가유산청 본문과 UNESCO 736·660 자료를 수집했다.
- 저장된 비교에서 collected_sources 3건을 재조회했다.
- 실제 탐구 화면 HTTP 200과 수집 내용 확인 영역을 확인했다.
- 다음 단계인 시대·구조·재료 추출과 항목별 근거 대조는 아직 적용하지 않았다.

□ 6.12 시대·구조·재료 추출 검증

- 전체 테스트 120개와 Ruff·형식 검사를 통과했다.
- 허위 인용·다른 유산 출처·메타데이터·유산군 설명·만료 자료 제외와 AI 실패 대체를 테스트했다.
- 실제 DataHub에서 호류지 영문 소개 555자를 수집했다.
- 실제 탐구 API에서 Gemini로 석굴암·호류지의 여섯 항목을 추출했다.
- 여섯 인용 모두 해당 유산·출처의 수집 본문에 존재하는 것을 검사했다.
- 여섯 항목 모두 needs_review이며 원문 일치를 의미 검증 완료로 간주하지 않았다.
- 저장된 비교에서 추출 항목 여섯 건을 재조회하고 화면 HTTP 200 및 근거 영역을 확인했다.
- 새 추출 값으로 비교·퀴즈 생성과 일반 역사적 주장 의미 대조는 다음 단계다.

□ 6.13 공식 근거 비교 및 수준별 퀴즈

- 전체 테스트 127개 통과. 근거 검사를 보완한 뒤 관련 테스트 7개를 재확인했다.
- 실제 수집·Gemini 추출한 여섯 항목을 재사용해 extracted 비교를 생성했다.
- 세 비교 항목과 실제 사용한 두 출처를 저장 및 재조회했다.
- 실제 API에서 초급·중급·고급 각 5문항을 생성하고 모두 5/5 채점과 근거 반환을 확인했다.
- 해당 퀴즈 화면 HTTP 200 및 추출 후보의 추가 확인 필요 안내를 확인했다.
- 기존 저장본을 변경하지 않고 새 비교를 만들었으며 퀴즈 생성에 Gemini를 재호출하지 않았다.
- 근거 부족 항목을 요약 데이터로 채우지 않고 검증 완료로 승격하지 않았다.
- 일반 역사적 주장에 대한 원문 의미 대조는 다음 단계다.

□ 6.14 원문 기반 주장 검토

- 전체 테스트 141개 및 Ruff·형식 검사 통과.
- 복합 주장 일부 근거 누락, 허위 인용, 다른 유산 출처, 오래된 자료·유산군 설명 제외를 검증했다.
- 실제 Gemini가 중첩 길이 제약 스키마를 거부해 호출 스키마를 단순화했다.
- 항목 수·문장 길이 제약은 로컬 Pydantic 검증으로 유지하고 과다 응답 거부 테스트를 추가했다.
- 실제 주장 API에서 목재 주장에 반박 후보와 유효한 원문 인용이 반환됐다.
- AI 의미 판정은 needs_review로 유지하며 source_match만 원문 문장 일치 의미로 verified 상태를 표시한다.
- 실제 영향 관계 주장에는 Gemini가 인용 없는 insufficient_evidence를 반환했다.
- 복합 주장 중 근거가 없는 부분의 문장을 API와 화면에 따로 표시한다.
- 사용자 주장·판정 응답은 DB에 추가 저장하지 않는다.
