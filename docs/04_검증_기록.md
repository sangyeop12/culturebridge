# 6. 수행 계획 및 검증 기록

□ 6.1 예외 처리

- 존재하지 않는 문화유산의 퀴즈: 오류 안내와 처음으로 버튼을 표시한다.
- 동일 문화유산 비교·퀴즈: 저장 및 생성 전에 서로 다른 대상 선택을 안내한다.
- 존재하지 않거나 대상이 다른 저장 ID: 복귀 화면을 표시한다.
- 잘못된 학습 수준: 초급으로 전환하고 전환 사실을 안내한다.
- DB 실패: 화면은 재시도·복귀를 안내하고 API는 상세 경로를 노출하지 않는 503을 반환한다.
- 질문 처리 실패: 알림을 표시하고 질문 버튼을 다시 활성화한다.
- 채점 실패: 결과 표시 및 완료 처리를 진행하지 않고 재시도를 안내한다.

□ 6.2 접근성 보완

- 키오스크 문화유산 선택을 기본 버튼으로 제공한다.
- 키보드 포커스 테두리, 질문·주장·검색 입력 이름, 퀴즈 문항별 라디오 그룹 이름을 제공한다.
- 질문·주장·채점 결과에 role=status 및 aria-live=polite를 적용한다.
- 문서 언어를 ko로 설정한다.
- 작은 화면에서 비교·문화유산 선택을 한 열로 배치한다.
- 키오스크 버튼과 라디오 선택 영역의 최소 높이를 72px로 설정한다.

□ 6.3 확인 결과

- 자동 테스트 58개 통과. 잘못된 UI 경로·저장 실패·API 503 응답을 포함한다.
- Ruff 검사 통과.
- 실제 브라우저에서 두 텍스트 입력의 접근 가능한 이름, 결과 알림 영역 2개,
  문서 언어 ko를 확인했다.
- 모바일 크기 변경 검사에서 브라우저 연결이 시간 초과되었다. 모바일 배치 실측,
  터치 높이 실측, 키보드 전체 이동 및 화면 읽기 프로그램 검증은 미완료다.
- 시간 초과 이후 뷰포트 복구도 응답을 확인하지 못했다. 해당 브라우저가 작은 크기로
  남아 있다면 사용자 화면에서 크기 설정을 확인해야 한다.
- 접근성 기준 전체 준수를 판정한 기록은 아니다.

□ 6.4 로컬 시연 준비 검증

- 실행 사전 점검: Python 3.12.14와 필수 패키지 import 정상.
- scripts/check.ps1: Ruff 검사·형식 검사 및 테스트 66개 통과.
- 검색 → 추천 → Agent 탐구 → 비교 저장/조회 → 자유 질문 → 주장 검증 →
  고급 퀴즈 채점 → 학습 기록 저장을 임시 DB에서 통합 검증했다.
- API 키가 설정된 상태를 모의해 오프라인 모드가 자동 호출을 막는지 확인했다.
- scripts/run.ps1 -Offline으로 실제 서버를 실행했다.
- /api/health·/·/kiosk·/comparisons·/docs 모두 HTTP 200을 확인했다.
- Gemini 실제 호출과 외부 배포는 이번 검증에 포함하지 않았다.
