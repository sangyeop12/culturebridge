# 체험 자동 초기화 재점검

점검일: 2026-10-25. 사용자 요청에 따라 실제 무조작 대기를 다시 확인한다.
사용자 학습 DB와 분리한 로컬 8082 서버를 사용하며 Gemini는 비활성화했다.
기존 8081 서버와 개인 설정은 변경하지 않는다.

## 점검 방법

- 체험 시작 → 석굴암 선택 → 호류지 예제 비교를 브라우저에서 실행했다.
- 비교 화면이 열린 시각은 08:26:56 UTC다.
- 운영 코드의 300초 설정을 바꾸지 않고, 페이지 타이머나 시계를 강제로 실행하지 않는다.
- 대기 중 브라우저의 해당 탭에 클릭·키 입력·터치를 보내지 않는다.
- 자동 이동 후 초기화 안내와 이전 비교 접근 차단을 확인한다.

## 실제 확대의 한계

Windows Chrome 제어는 도구가 현재 URL을 판별하지 못해 안전상 중단됐다.
해당 차단을 해제하거나 우회하지 않았다. 별도 지원되는 앱 내 브라우저에서 확대
단축키를 적용했지만, 적용 전후 CSS 뷰포트 너비 1280·기기 배율 1·시각 배율 1로
변화가 없었다. 실제 200% 확대는 미확인으로 남긴다.
좁은 화면이나 CSS 확대를 실제 브라우저 확대 점검으로 대체하지 않는다.

## 결과

08:26:56 UTC에 비교 화면을 열고 조작 없이 대기했다. 08:32:04 UTC 이후 조회에서
`/kiosk?reset=timeout`으로 자동 이동한 상태와 “이전 체험을 종료했어요. 새로운 체험을
시작할 수 있어요.” 안내를 확인했다. 300초를 줄이지 않은 실제 무조작 대기 결과이며,
정확한 콜백 실행 시각을 계측한 것은 아니다.

이후 같은 브라우저에서 직전 비교의 저장 ID로 다시 접근했을 때 “비교 결과를 찾을 수
없습니다.”가 표시돼, 자동 초기화 전 기록을 새 체험에서 열 수 없음을 확인했다.
DB 기록을 삭제하지 않고 접근만 차단했다.

전체 통합 검사는 Ruff 린트·248개 파일 서식 검사·789개 테스트를 통과했다
(Python 3.13, 262.49초). 통합 검사에서는 실제 Gemini를 호출하지 않았다.
원시 DB와 화면 증거는 Git에서 제외되는 `outputs/final-live-20261025/`에 보존했다.
점검 탭과 별도 서버는 종료했다.
