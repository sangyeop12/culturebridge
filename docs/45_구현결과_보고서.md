# CultureBridge 구현 결과 보고서

작성 기준: 2026-10-23. 작성·개발 담당: 김상엽.
최종 제출 전 팀 검토가 필요한 보고서 초안이다.

## 1. 서비스 목적

문화유산의 공식 자료를 읽고, 다른 나라의 유산과 비교하며, 대화와 퀴즈로
이해를 확인하는 역사 교육 웹 서비스다. 학습자의 관심과 목표를 대화에서
추정하고 이후 설명과 학습 경로에 반영한다. 관심 추정은 확정된 성향이
아니므로 부정·목표 변경을 반영하고 사용자가 수정할 수 있게 했다.

## 2. 구현 범위

- 홈에서 한국어 이름·별칭으로 검색하고 공식 상세 자료로 이동한다.
- 해외 비교를 기본으로 제공하고 국내 비교는 별도 경로로 제공한다.
- 시대·구조·재료·종교적 배경의 근거를 확인하고 비교 대상을 추천한다.
- 초급은 핵심 설명과 용어 풀이, 중급은 항목별 설명, 고급은 공식 원문을 제공한다.
- 자유 질문, 주장 검토, 학습 코스, 퀴즈와 오답 복습을 연결한다.
- 설명 방식은 설정에서, 관심·목표는 나의 학습에서 확인·수정한다.
- 익명 세션별 학습 기록과 결과 출력을 제공한다.
- 대화에서 해외 개별 유산 검색을 실행하고 UNESCO 목록은 공식 링크로 안내한다.

일반 역사 인물·사건은 현재 공식 포털 안내 수준이다. 모든 역사 주제를 원문
검색부터 학습까지 처리하는 범용 역사 Agent를 완성했다고 주장하지 않는다.

## 3. 기술과 실행 환경

지원 Python 범위는 3.12 이상 3.14 미만이다. 설치 버전은 저장소의 잠금 파일을
기준으로 재현한다. Python 3.12와 3.13 환경을 별도로 검증한다.

| 영역 | 사용 기술 | 역할 |
|---|---|---|
| 웹 화면 | NiceGUI | 검색·비교·대화·설정·학습 기록 화면 |
| 서버 | FastAPI, Uvicorn | 페이지·API·세션 요청 처리 |
| Agent | LangGraph | 계획, 도구 실행, 근거 확인, 응답과 재탐색 |
| 생성형 AI | Google Gen AI SDK, Gemini | 관심 추정, 근거 기반 설명, 이해도 판단 |
| 외부 자료 | HTTPX, defusedxml | 공식 자료 요청과 안전한 XML 처리 |
| 저장 | SQLite | 비교·퀴즈·대화·학습 상태와 자료 캐시 |
| 검증 | pytest, Ruff | 기능 회귀 검사와 코드 정적 검사 |

API 키는 로컬 비밀 설정으로 관리하며 GitHub에 올리지 않는다. 실제 자료와
연동 결과, 학습자 기록도 공개용 문서와 분리한다. 설치·실행 명령은 README를 따른다.

## 4. 공식 자료와 이용 조건

국가유산청 검색·상세·위치 정보와 UNESCO 세계유산 목록을 활용한다. 해외 개별
유산 자료 25개와 무료 공개 보충 기록을 관리한다. 개별 건물과 등재 유산군을
구별하고 창건·건립·재건 연대를 섞어 설명하지 않도록 검사한다.

연결 성공과 번역·AI 처리·재배포 허가는 별개다. 원문별 이용 조건에 따라
처리 경로를 제한한다. UNESCO 목록은 메타데이터와 공식 링크 안내이며 본문을
AI로 전송하지 않는다. 접수 자동 회신을 기관의 허가로 기록하지 않는다.

한국고고학사전 공개 API는 키 없는 실제 응답을 확인했다. 그러나 조회 항목의
개별 권리 조건과 응답 필드 순서가 안내 예시와 달라, 본문을 AI에 보내는
추가 연동은 보류했다. 표준국어대사전은 실제 키 등록·정상 응답 확인이 남았다.

참조: [국가유산청](https://www.khs.go.kr/),
[UNESCO XML](https://whc.unesco.org/en/list/xml/),
[한국고고학사전 API](https://portal.nrich.go.kr/kor/apiView.do?idx=39&menuIdx=665).

## 5. Agent 동작

학습자의 질문과 저장된 학습 상태를 바탕으로 실행할 행동을 선택한다.
자료 검색·읽기 도구를 실행하고 근거가 부족하면 제한된 횟수 안에서 검색어나
후보를 바꾼다. 무한 실행을 막기 위해 호출 수·시간·중복 행동을 제한한다.

해외 자료는 검색 결과에 존재하는 등록 ID만 읽는다. 임의 URL을 생성해 수집하지
않는다. 근거·권리 조건을 통과하지 못하면 추측으로 내용을 채우지 않고 원문
링크나 보류 이유를 제공한다. 퀴즈 이후에는 답과 이유, 누적 상태를 참고해
보충 설명·다른 문제·심화 학습을 선택한다.

생성 설명에는 원문 인용 검증과 별도 의미 검사를 적용한다. 이번 검토에서
추측 연대를 확정 표현으로 바꿀 위험을 발견해 불확실성 표현을 보존하도록
검사를 보강했다. 자동 검사 역시 역사 전문가의 최종 판단을 대신하지 않는다.

## 6. UX/UI 정리

공통 색·타이포그래피·화면 폭과 탐색 구조를 통일했다. 학습 화면에는 질문과
학습 내용에 필요한 조작을 두고, 설명 방식은 설정 화면으로 분리했다.
돌아가기 링크는 검색 조건과 학습 수준을 유지한다. 사용자 화면에서 기술적인
실행 정보·내부 저장 식별자 노출을 줄이고 친근한 교육 서비스 표현을 유지했다.

## 7. 검증 결과

| 검증 | 확인 결과 | 해석 범위 |
|---|---|---|
| Python 3.12 자동 검사 | 675개 통과 | 해당 환경의 회귀 검사 |
| Python 3.13 자동 검사 | 675개 통과 | 해당 환경의 회귀 검사 |
| 해외 개별 원문 연결 | 25개 새 수집 성공 | 연결 상태이며 이용 허가와 별개 |
| 수준별 읽기 | 75개 설명의 원문 보존 확인 | 역사 전문가 승인과 별개 |
| 대표 코스 | 5개 코스 × 3수준, 15개 경로 | 합성 입력으로 기능 흐름 확인 |
| 퀴즈·복습 | 경로별 내용 문항 5개, 정답·오답 채점과 복습 확인 | 실제 학습 효과 측정 아님 |
| 백업 복구 | 32개 테이블 행 수 일치, 무결성·외래키 정상 | 별도 복원 DB 사용 |
| 복구 후 화면 | 주요 화면 6곳 HTTP 200 | 다른 PC·휴대전화 확인과 별개 |
| 실제 Gemini | 관심 긍정·부정·변경, 오개념·이유 부족, 설명 표본 확인 | 제한된 사례의 실제 응답 |

Gemini 첫 실행에서 503과 대체 설명을 확인했다. 실패를 숨기지 않고 보존한 뒤
선택 사례를 재검사했다. API 응답은 공급자 상태와 호출 한도에 영향을 받는다.
개인 질문·원문이 포함된 진단 파일과 DB는 GitHub에 포함하지 않는다.

## 8. 남은 한계와 사용자 확인

- 외부 원문 이용 허가 회신과 역사 전문가의 최종 검수는 남아 있다.
- 실제 안드로이드 음성 인식·권한·PWA 설치와 재실행 확인이 필요하다.
- 키보드·화면 확대·키오스크의 실제 사용성, 팀원 PC 새 설치 확인이 필요하다.
- 실제 학생 수업과 난도·추천 적합성·복습 효과에 대한 사용자 의견이 필요하다.
- 일반 역사 원문 검색·읽기 범위를 확대하려면 출처별 조건과 응답 구조 검토가 필요하다.
- 최종 보고서·발표 자료는 팀 검토 후 제출해야 한다.

## 9. 향후 작업 기준

기능 확대보다 현재 근거의 정확성과 학습 경험의 확인을 우선한다. 미확인 사실을
추가하지 않고, 실제 사용 결과에 따라 어려운 설명·반복 문항·부자연스러운 비교를
보완한다. WBS의 완료는 해당 작업 범위의 증거에 따라 갱신하며 남은 사용자
확인과 외부 허가를 자동 검사 결과로 대체하지 않는다.
