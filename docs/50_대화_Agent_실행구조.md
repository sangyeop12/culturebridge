# 대화 Agent 실행 구조와 검증 범위

## 구현 기준

서비스의 모든 버튼이 AI일 필요는 없다. 검색·저장·채점·로그인·환경 설정은 일반 소프트웨어 기능이며,
학습 목표를 수행하는 상위 제어기가 관찰을 받아 다음 도구와 활동을 선택하는지가 핵심이다.
특정 교수·전문가의 평가나 교육 효과를 보장하지 않는다.

대화의 제어 루프는 다음 정보를 사용한다.

1. 사용자의 현재 질문·목표, 현재 주제의 대화, 잠정 학습 기록을 읽는다.
2. 모델이 필요한 계획과 다음 행동·인자를 선택한다.
3. 등록된 검색·읽기·사전·후보 탐색·비교·퀴즈·오답 근거 도구를 실행한다.
4. 실제 실행 결과의 성공·빈 결과·실패·근거 부족·차단 상태를 다음 계획에 전달한다.
5. 같은 목표라도 다른 검색어·다른 후보·보충 활동·다음 사례·정리를 선택할 수 있다.
6. 설명·확인 질문 또는 퀴즈를 보여주면 사용자 응답을 기다린다.

모델이 임의의 코드·URL을 실행하거나 외부 기관의 허가 조건을 변경할 수는 없다.
허용된 도구 안에서의 자율성이지 무제한 실행 권한이 아니다.

## 이번 변경

- 이해도 판단 전용 평가 결과를 상위 계획에 전달한다. 평가 결과의 기존 `check`/`review`
  표현을 그대로 다음 행동으로 실행하지 않는다. 계획 모델의 평가 필드도 새 판단으로 저장하지 않는다.
- 기존 비교 흐름을 상위 Agent가 호출하는 도구로 연결했다. 비교 내부의 자료 수집·추출·검사는
  단계형이다. 대화 경로에서는 비교가 끝났다는 이유만으로 퀴즈를 강제 생성하지 않는다.
- AI가 적합한 비교 저장본으로 퀴즈를 준비할 수 있다. 문제·선택지만 대화에 전달하며 정답 인덱스와
  해설은 제출 전 대화 상태에 넣지 않는다. AI 행동 목록에 답안 제출 도구는 없다.
- 학습자의 답안 제출 후 실제 채점 기록을 관찰한다. AI는 오답 근거 조회 후 복습 활동을 선택하거나
  다른 학습으로 진행할 수 있다. 대화 이력은 유지한다.
- AI가 보충 설명·단계별 안내·대조·다른 질문·심화 활동을 선택할 수 있다. AI가 사용 불가능하거나
  자동 활동을 선택한 경우의 기존 규칙 기반 보조는 유지한다. 이를 전부 AI 판단이라고 부르지 않는다.
- 학습 계획과 실제 실행 과정은 화면에서 펼쳐볼 수 있다. 이는 실행 요약이며 숨은 사고 과정이 아니다.

## 보호 장치

- 검색·읽기·후보에서 확인한 개별 대상만 비교한다. UNESCO 목록 메타데이터를 개별 원문처럼 쓰지 않는다.
- 목표 근거가 부족한 비교는 퀴즈 근거로 승인하지 않는다. 인용 적합성 검사가 역사 전문가의 승인이라는 뜻은 아니다.
- 같은 대화에서 생성하고 같은 학습자가 소유한 비교·퀴즈만 사용한다.
- 해외 비교 목표를 국내 비교로 몰래 바꾸지 않는다.
- 한 턴의 기본 도구 실행 한도는 6회, 계획 시도는 그보다 2회 많은 범위로 제한한다.
  동일 도구·동일 인자는 재실행하지 않고 중복 관찰을 남긴다.
- 턴 시작부터 시간 예산을 검사하고 각 외부 요청에도 제한을 둔다. 이미 진행 중인 내부 요청을
  즉시 취소하거나 총 벽시계 시간을 정확히 45초로 자른다는 보장은 아니다.
- 중단·건너뛰기·주제 변경은 사용자가 선택한다. 새 주제에는 이전 활동의 도구 산출물을 재사용하지 않는다.
- 퀴즈 점수, 한 번의 답변, 활동 정리는 숙달 확정이 아니다.

## 검증의 구분

`tests/test_agent_orchestration.py`는 격리된 DB와 합성 원문으로 실제 그래프·저장·채점·복습을
실행한다. 계획 모델은 통제된 응답으로 대체한다. 다음 계약을 검증하지만 실제 모델 품질을 증명하지는 않는다.

- 비교와 퀴즈 실행 분리
- 비교 → AI의 퀴즈 선택 → 학습자 제출 → 채점 → AI의 오답 근거 조회 → 복습
- 제출 전 정답·해설 비노출, AI의 답안 제출 행동 금지
- 실행 실패를 관찰한 검색 도구 변경, 중복 호출 방지
- 타 학습자 저장본 차단, 미확인 ID·비교 범위 변경 차단
- 시간 예산 확인, 주제 변경 시 현재 활동 초기화
- 별도 평가 결과를 계획에 전달하고 평가의 기존 행동에 묶이지 않는지 확인

`scripts/check_agent_planning.py --live`는 실제 Gemini를 호출한다. 일반 API 사용량이 발생한다.
학습자의 실제 기록과 분리된 임시 DB, 합성 관찰만 사용한다. 정해진 정답 도구를 코드로 실행시키는
대신 모델이 반환한 행동을 기록한다. `--case`로 필요한 사례만 다시 확인할 수 있다.

2026-10-24의 제한된 관찰에서는 다음을 확인했다.

- 빈 해외 검색 결과를 전달하자 새 검색어 `pagoda`로 `search_world`를 선택했다.
- 충분한 합성 비교 저장본과 퀴즈 요청을 전달하자 해당 ID로 `quiz`를 선택했다.
- 잠정 이해도 지지와 다른 재료의 사례를 골라 비교해 달라는 요청에는 기존 대상 ID로 `discover`를 선택했다.
- 첫 검색 사례에서는 한 차례 서버 오류가 발생했다. 이후 별도 재실행에서 위 선택을 관찰했다.
- 모호한 “다음 재료를 볼게요”에는 되묻기도 했다. 자율적 진행이 모든 표현에서 일관되게
  보장되는 것은 아니다. 명확한 요청과 모호한 요청을 같은 통과 사례로 계산하지 않았다.

실제 모델 관찰은 합성 도구 결과를 입력한 단일 계획 단계 검사다. 실시간 해외 수집부터 학생의 답변까지
모두 실제로 진행한 장기 학습 시험이나 역사 전문가 검토가 아니다. 호출 가능 여부·응답 선택은 달라질 수 있다.
실제 학생의 학습 효과, 휴대전화 음성·설치 검증은 별도 항목으로 남는다.

## 자동 검증 결과

- Python 3.13: 최종 전체 검사 719개 통과.
- Python 3.12: 직전 전체 검사 718개 통과. 이후 추가한 범위 보호를 포함한 관련 검사 69개 통과.
- 새 Agent 실행 계약 검사 13개 통과. 화면 렌더링만으로 계획 모델을 호출하지 않는지도 확인했다.
- Ruff 코드 검사 및 Git 공백 오류 검사 통과.
- 최신 로컬 서버의 `/learn` 응답 200, 브라우저에서 학습 시작 화면의 정상 표시 확인.

이 수치는 실행 계약·회귀 검사 결과이며, 실제 학생의 학습 효과나 역사 전문가의 최종 승인 비율이 아니다.
