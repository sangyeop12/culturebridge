# 안드로이드 로컬 실기기 점검

현재 상태: 사용자가 현재 USB 연결이 어렵다고 확인했다. 실제 기기 검증은 진행 중으로 남긴다.
담당자: 김상엽. 렌더나 다른 공개 서버를 만들지 않는다.

## 연결

PC의 로컬 서버를 켜 둔다. 휴대전화의 `127.0.0.1`은 PC를 가리키지 않는다.
같은 Wi-Fi의 평문 IP 주소로 열리는 것과 음성·설치에 필요한 보안 문맥은 별개다.

Chrome 공식 USB 포트 전달 안내:
https://developer.chrome.com/docs/devtools/remote-debugging/local-server?hl=en

1. 신뢰하는 PC에 USB로 연결하고 휴대전화 개발자 옵션의 USB 디버깅을 허용한다.
2. PC Chrome의 `chrome://inspect/#devices`에서 기기를 확인한다.
3. Port forwarding에서 기기 포트 `8081`을 PC의 `localhost:8081`로 전달한다.
4. 휴대전화 Chrome에서 `http://localhost:8081/learn`을 연다.
5. 점검 후 필요하지 않으면 USB 디버깅과 해당 PC의 디버깅 허용을 해제한다.

실제 기종·Android 버전·Chrome 버전과 실행 결과를 기록한다. 개발 환경의 loopback 예외를
사용한 점검이며, 일반 서비스의 HTTPS 배포 검증과 같지 않다. 설치돼도 PC 서버·USB 연결을
대신하는 독립 앱이 되지는 않는다.

## 확인 항목

| 항목 | 기대 결과 | 실제 결과 |
|---|---|---|
| 페이지·직접 입력 | 화면이 열리고 텍스트를 입력할 수 있음 | 확인 대기 |
| 마이크 허용 후 말하기 | 한국어를 글로 옮김. 자동 전송하지 않음 | 확인 대기 |
| 음성 내용 수정 | 수정한 내용으로 직접 보낼 수 있음 | 확인 대기 |
| 마이크 거부 | 오류 안내 뒤 직접 입력 가능 | 확인 대기 |
| 녹음 중 직접 수정·중단 | 늦게 도착한 음성으로 덮어쓰지 않음 | 확인 대기 |
| 화면 숨김·잠금·30초 제한 | 녹음을 멈추고 기존 입력 보존 | 확인 대기 |
| 홈 화면 추가 | `/install` 또는 Chrome 메뉴의 설치/추가 가능 여부 확인 | 확인 대기 |
| 설치 후 재실행 | 학습 화면이 열림. 기록 유지 여부도 구분해서 확인 | 확인 대기 |
| 네트워크·USB 연결 해제 | 개인 기록을 캐시하지 않고 연결 안내 제공 | 확인 대기 |

마이크 거부 후 재허용은 Chrome의 해당 사이트 권한에서 사용자가 직접 조정한다.
권한 허용·기기 설정·설치를 자동으로 대신 승인하지 않는다.
브라우저 미지원과 권한 오류, 실제 음성 인식 품질을 따로 기록한다.

기기 점검 결과를 받기 전에는 WBS의 실기기 항목을 완료로 바꾸지 않는다.
