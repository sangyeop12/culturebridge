# CultureBridge

한국·중국·일본의 문화유산을 공식 자료에 근거해 비교하고, 학습 수준에 맞는 설명과 퀴즈를 제공하는 AI Agent 기반 교육 플랫폼입니다.

## 1. 현재 구현 범위

- 문화유산 목록·상세 조회 API
- 국가유산청 실제 목록·상세 API 검색, 원문·출처·조회 시각 수집과 SQLite 캐시
- 선택 문화유산을 기준으로 한 비교 후보 추천
- 두 문화유산의 구조·재료·시대·종교적 배경 비교
- 초급·중급·고급 학습 수준 선택
- 수준별 비교 해설·학습 목표·퀴즈: 초급 관찰, 중급 비교, 고급 근거 판단
- 네 역할의 Agent 흐름 골격
- 4개 Agent의 탐구 실행 API
- 공식 출처 범위 안에서 답하는 자유 질문 화면과 API
- 역사적 주장 검증 화면·API: 재료·시대·구조의 단일 사실 대조와 근거 표시
- 비교 결과·출처 스냅샷 SQLite 저장, 저장된 비교 목록과 다시 열기
- 5문항 퀴즈 화면·채점·해설과 SQLite 학습 기록
- NiceGUI 기반 웹 화면과 전용 키오스크 체험 흐름
- 키오스크용 대형 터치 버튼·수동 초기화·5분 미사용 자동 초기화
- 잘못된 비교·퀴즈 주소의 복귀 안내, DB 실패 안내 및 API 503 응답
- 키보드 선택 버튼·포커스 표시·입력 이름·결과 알림 영역·모바일 세로 비교 배치
- 공식 출처와 검증 상태를 포함한 샘플 데이터

## 2. 실행 방법

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
python -m culturebridge.main
```

브라우저에서 `http://127.0.0.1:8080`을 열면 됩니다. API 문서는 `/docs`에서 확인할 수 있습니다.
박물관형 터치 체험은 `http://127.0.0.1:8080/kiosk`에서 시작합니다.
저장된 비교는 `http://127.0.0.1:8080/comparisons`에서 확인합니다.
목록은 계정별 기록이 아닌 이 기기의 공용 비교 결과입니다. 질문 입력은 저장하지 않습니다.

이미 설치된 프로젝트는 다음 명령으로 점검하고 시연할 수 있습니다.

```powershell
.\scripts\run.ps1 -CheckOnly -Offline
.\scripts\check.ps1
.\scripts\run.ps1 -Offline
```

`-Offline`은 키 설정 여부와 관계없이 앱의 자동 Gemini 호출을 끕니다.
다른 포트는 `-Port 8081`로 지정합니다. 서버 실행 중에는 터미널을 유지합니다.
자세한 순서는 [실행·5분 시연 안내](docs/05_실행_시연_안내.md)를 참고하세요.

## 4. 데이터 원칙

- 공식 기관 자료를 우선합니다.
- 출처 제목·기관·URL·조회일을 함께 저장합니다.
- UNESCO 출처에는 요약과 자료 범위를 함께 표시합니다. 문화유산은 3건, 출처는 4건입니다.
- 확인되지 않은 내용은 사실처럼 단정하지 않습니다.
- 생성형 AI는 초안 작성에만 사용하며, 검증 상태를 별도로 표시합니다.
- 주장 검증은 등록된 요약 데이터와 대조합니다. 실시간 원문 검색은 아직 지원하지 않습니다.
- 예: `석굴암의 재료는 화강암이다`. 일치하면 확인됨, 불일치하면 추가 확인 필요,
  지원하지 않는 문장이나 영향·인과 관계는 근거 부족으로 표시합니다.

## 5. Gemini 연동 점검

로컬 `.env`의 `GEMINI_API_KEY`와 `GEMINI_MODEL`을 설정한 뒤 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m culturebridge.check_gemini
```

`success`는 실제 AI 응답 수신, `failed`는 호출 실패, `not_configured`는 키 미설정입니다.
실제 호출은 설정한 계정의 API를 사용합니다. AI 결과는 추가 확인 필요로 표시합니다.
앱은 호출 실패·빈 응답 시 로컬 답변으로 전환하며 요청 제한시간 기본값은 15초입니다.
이번 검증에서는 키가 없어 실제 호출은 하지 않았고 대체 응답과 자원 정리는 모의 테스트했습니다.

출처 확인: [석굴암 UNESCO](https://whc.unesco.org/en/list/736/),
[호류지 UNESCO](https://whc.unesco.org/en/list/660/),
[실크로드 UNESCO](https://whc.unesco.org/en/list/1442/),
[Google SDK](https://googleapis.github.io/python-genai/).

## 6. 국가유산청 공식 자료 연결

시작 화면의 **국가유산청 공식 자료 검색** 또는 `/official`에서 이름을 검색합니다.
목록에서 **공식 설명 보기**를 누르면 상세 원문을 수집·저장합니다. 별도 API 키는 없습니다.

- 목록: `GET /api/official/heritages?q=석굴암&page=1&page_size=10`
- 상세: `GET /api/official/heritages/11/0000240000000/37`
- 외부 API: `https://www.khs.go.kr/cha/SearchKindOpenapiList.do` 및 `SearchKindOpenapiDt.do`
- 상세 XML·정규화 본문·URL·조회 시각은 로컬 `official_documents` 테이블에 보관합니다.
- 상세 캐시는 기본 24시간, 외부 요청 제한시간은 10초입니다. 오래된 캐시로 대체할 때는
  갱신 필요와 연결 실패를 표시합니다. 검색 실패는 오류 안내 후 재시도할 수 있습니다.
- 석굴암 원문을 수집한 뒤 자유 질문을 하면, 유효한 캐시 본문을 Gemini에 함께 전달합니다.
  오래된 본문은 AI 근거에서 제외합니다. AI 응답의 출처 링크에 API 원문이 표시됩니다.
- 일반 검색 결과 전체를 자동으로 비교·퀴즈 데이터로 변환하지 않습니다. 기존 3건의
  검토된 비교 항목은 유지하며, 그 외 유산은 공식 설명 조회를 제공합니다.
- 외부 자료는 지시가 아닌 근거 데이터로 전달하고 AI 답변은 추가 확인 필요로 유지합니다.
- 이미지 다운로드·재배포 기능은 포함하지 않습니다. 원문 활용 시 해당 기관 이용 조건을 확인합니다.

설정 변경이 필요하면 `.env`에 `CULTUREBRIDGE_HERITAGE_TIMEOUT_SECONDS=10`,
`CULTUREBRIDGE_HERITAGE_CACHE_HOURS=24`를 지정할 수 있습니다.

## 7. 공식 위치정보 연결

공식 설명 화면에서 **공식 위치정보 불러오기**를 누르면 국가유산공간정보 API
`https://gis-heritage.go.kr/openapi/xmlService/spca.do?ccbaKdcd=11` 등을 조회합니다.
별도 키 없이 서버에서 요청하며 유산명·지정종목·시군구가 일치하는 위치만 표시합니다.

- 앱 API: `GET /api/official/heritages/{kind}/{number}/{region}/location`
- 공간정보 API의 cnX·cnY는 UTM-K 원좌표로 표시하며 위도·경도로 임의 해석하지 않습니다.
- 위도·경도는 국가유산청 상세 API의 latitude·longitude를 사용하고 출처를 따로 표시합니다.
- 유효한 위도·경도가 있으면 외부 OpenStreetMap 지도 링크를 제공합니다.
- 좌표계 변환·지정구역·보호구역 경계 레이어는 이번 연결에 포함하지 않습니다.
- 종목별 원문 XML은 official_location_feeds 테이블에 24시간 캐시합니다.
  외부 장애로 이전 좌표를 사용할 때는 갱신 필요를 표시합니다.
- 좌표 미제공, 이름 불일치, 같은 이름의 중복 후보는 위치를 확정하지 않습니다.

좌표 체계와 지도 서비스 안내: [국가유산공간정보 Open API](https://gis-heritage.go.kr/helpAPI.do).

## 8. UNESCO 영문 XML 연결

`/unesco`에서 이름·국가·등재 ID를 검색합니다. 서버는 UNESCO DataHub의 공식
세계유산 데이터셋 `whc001` JSON API를 요청하고 받은 자료를 24시간 캐시합니다.
API는 `GET /api/unesco/heritages?q=Japan&limit=20&offset=0`입니다.

기존 `whc.unesco.org/en/list/xml`은 Cloudflare 확인 페이지로 HTTP 403을 반환하지만,
공식 DataHub API는 정상 수집됩니다. 화면의 **공식 데이터 새로고침**으로 즉시 갱신할 수
있으며 캐시 만료 후 조회 시에도 자동 갱신합니다. 별도 API 키는 필요하지 않습니다.
API 장애 시 기존 자료를 유지하고 갱신 실패를 표시합니다.
대체 자료로 공식 사이트에서 직접 내려받은 영문 XML도 다음 명령으로 가져올 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m culturebridge.import_unesco "C:\Users\sun\Downloads\unesco.xml"
```

위 경로는 예시이므로 실제 다운로드한 파일 경로로 바꿉니다. 가져오기 전에 XML 형식을
검증하고, 잘못된 파일은 기존 데이터를 덮어쓰지 않습니다. 원문은 로컬 SQLite에만
보관하며 GitHub에는 업로드하지 않습니다. 검색 UI는 처음 20건을 표시합니다.

목록 검색 화면은 이름·국가·등재연도·공식 링크를 표시하며 자체적으로 Gemini를 호출하지 않습니다.
등재연도는 건립연도가 아닙니다. DataHub와 XML은 각기 출처·형식·이용 조건을 저장합니다.
[공식 DataHub 데이터셋](https://data.unesco.org/explore/dataset/whc001/information/)은
CC BY-SA 4.0으로 안내됩니다. 수집 API·데이터셋·개별 유산·이용 조건 링크를 표시합니다.
직접 가져온 XML에는 [XML 배포 이용 조건](https://whc.unesco.org/en/syndication)이 적용됩니다.

### 한글 매칭과 자동완성

UNESCO 화면에서 한글 별칭과 국가명을 검색할 수 있습니다. 석굴암·불국사는 ID 736,
호류지·법륭사는 660, 실크로드·대안탑은 1442로 연결합니다. 대안탑은 독립 등재 항목이
아니므로 실크로드 등재 유산군을 표시합니다. 한국·대한민국·일본·중국은 국가 필터로
연결합니다. 공식 원문 이름을 번역하거나 바꾸지 않습니다.

입력 중 최대 8개 제안을 표시하며 클릭하거나 Tab 자동완성 후 Enter로 검색할 수 있습니다.
자동완성은 로컬 캐시에서 구성하므로 입력할 때마다 외부 API·Gemini를 호출하지 않습니다.
공식 영문 이름은 전체 목록에 대해 제안하고 한글 별칭은 현재 위 항목만 지원합니다.
추가 별칭은 `services/unesco_service.py`의 매핑에 검토 후 등록합니다.
추천 API는 `GET /api/unesco/suggestions?q=호&limit=8`입니다.

## 9. Agent 공식 자료 탐구

문화유산 선택 → 비교 후보 → **공식 자료로 Agent 탐구**를 누릅니다.
`/research/seokguram/horyuji` 또는 기존 `POST /api/explorations`에서도 실행할 수 있습니다.

- 역사 탐구 Agent가 선택한 양쪽 유산의 공식 자료를 수집합니다.
- 석굴암: 국가유산청 상세 원문과 UNESCO 등재 메타데이터.
- 호류지: 공식 DataHub 영문 소개. 대안탑: 실크로드 유산군 영문 소개 및 메타데이터.
- 비교 결과에 수집 본문·자료 조회 시각·출처·이용 조건·수집 상태를 함께 저장합니다.
- 일부 자료가 없거나 오래되면 탐구 결과에 추가 확인 필요를 표시합니다.
- 수집했다는 사실은 내용 전체가 검증됐다는 뜻이 아닙니다. 비교 항목·퀴즈는 아직
  기존 검토 데이터로 작성합니다. 새 추출 값으로 비교·퀴즈를 구성하는 작업은 다음 단계입니다.

## 10. 시대·구조·재료 추출과 근거 연결

Agent 탐구에서 국가유산청 개별 원문과 DataHub 개별 소개를 사용해 세 항목을 추출합니다.
Gemini 키가 활성화돼 있으면 구조화된 JSON으로 추출하고, 호출 실패 또는 키 미설정 시
항목 관련 원문 문장을 찾는 로컬 방식으로 전환합니다. 두 유산 × 세 항목의 결과를 저장합니다.

- 추출 값·출처 ID·원문 인용·출처 URL·추출 방식·검증 상태를 표시합니다.
- 인용 문장이 해당 유산의 실제 수집 본문에 정확히 존재하는지 검사합니다.
- 존재하지 않는 인용·다른 유산 출처·메타데이터·유산군 설명·오래된 자료는 제외합니다.
- 근거가 없으면 값을 추측하지 않고 근거 부족으로 표시합니다.
- 원문 일치는 의미 검증이 아니므로 근거가 있는 추출도 추가 확인 필요로 유지합니다.
- 기존 저장 결과는 재조회 시 다시 추출하지 않습니다.
- 현재 이 단계는 추출 후보와 근거를 표시하며, 기존 비교·퀴즈를 자동 덮어쓰지 않습니다.

## 11. 공식 근거 기반 비교·퀴즈

새 Agent 탐구 결과는 basis=extracted로 저장합니다. 시대·구조·재료의 추출 후보를
항목별로 나란히 표시하고, 근거가 없는 값은 근거 부족으로 남깁니다. 공통점·영향 관계를
자동 확정하지 않으며 원문 일치와 의미 검증을 구분합니다.

저장된 탐구 화면에서 학습 확인 퀴즈를 열면 같은 비교 ID를 사용합니다. 초급은 출처·인용
찾기와 추출 후보 읽기, 중급은 같은 항목 대조, 고급은 원문 범위와 해석의 한계 판단을
다루는 5문항을 구성합니다. 원문 없이 새 역사적 사실을 생성하지 않습니다.

- POST /api/quizzes에 comparison_id를 전달하면 근거 기반 퀴즈를 생성합니다.
- 정답·해설은 답안 제출 전에 응답에서 제외합니다. 제출 후 저장된 원문 근거를 제공합니다.
- 유효한 근거가 하나도 없거나 비교 대상이 다르면 422로 안내합니다.
- 퀴즈를 만들거나 재조회할 때 Gemini를 다시 호출하지 않습니다.
- comparison_id가 없는 기존 퀴즈는 검토된 기본 데이터를 사용합니다.
- 기존 저장본은 당시 내용을 유지합니다. 새 비교 방식은 새 Agent 탐구에서 적용합니다.

## 12. 저장된 공식 원문으로 주장 검토

공식 자료가 포함된 비교 화면의 주장 검증은 같은 비교 저장본을 사용합니다.
요청은 `POST /api/claims/verify`에 `comparison_id`를 추가합니다. 다른 비교 대상이나
존재하지 않는 저장본은 거부합니다. 원문 수집을 다시 실행하거나 추출 후보를 사실로
간주하지 않습니다.

- Gemini는 전체 문장을 개별 주장으로 나눠 지지·반박 후보의 원문 인용을 제안합니다.
- 코드가 출처 ID·유산 ID·본문 문장 일치를 재검사합니다.
- 허위 인용·다른 유산 출처·메타데이터·유산군 설명·오래된 자료는 제외합니다.
- 지지·반박·혼합 후보는 모두 추가 확인 필요이며 거짓/참의 최종 판정이 아닙니다.
- 인용이 없는 주장 부분은 근거 부족으로 안내합니다.
- 원문 한 문장과 완전히 동일한 입력만 원문 일치로 확인됨을 표시하며 독립 사실 검증을 뜻하지 않습니다.
- 키 미설정·오프라인·호출 실패 시 단일 항목의 관련 근거만 표시하거나 근거 부족으로 남깁니다.
- 사용자 주장과 검토 답변은 DB에 추가 저장하지 않습니다.
- comparison_id가 없는 기존 API는 등록 요약의 제한된 문장 대조 방식을 유지합니다.
